八個必要元件

它們各自負責什麼？

把系統想成一間研究室：資料不是進來就能算，每個元件都在避免一種常見錯誤。

C01

資料來源與版本

像資料倉庫與收據。 保存來源、授權、取得時間、checksum、筆數與涵蓋範圍。完成後，結果不會變成「不知道從哪裡來的數字」。
部分完成
C02

Dataset Contract

像每份資料的使用說明書。 定義一筆紀錄代表什麼、時間和位置怎麼解讀、哪些欄位可能缺值。這是目前已站穩的底座。
基礎完成
C03

Semantic Registry

像 GIS 知識字典。 分開來源紀錄、衍生指標、proxy 與 hypothesis，也寫明禁止結論。完成後，Agent 才知道資料「能不能這樣解讀」。
三張語意卡完成
C04

Recipe／Skill

像標準研究方法。 告訴 Agent 遇到某類問題該依什麼順序用工具、要檢查什麼、什麼情況必須停下來。
待建立
C05

Query Executor

像受控的資料領用櫃台。 控制讀取範圍、成本與權限，留下查詢收據。已能支援目前的三類 pilot。
基礎完成
C06

GIS／時序引擎

像研究室裡的計算設備。 現在有 nearby 與基本彙總；接下來要補行政區 join、路網、raster、時間趨勢與不確定性。
部分完成
C07

Evidence Guard

像研究審稿人。 檢查來源、缺值、STALE、proxy、位置精度與因果跳躍，避免工具成功卻產生錯誤結論。
基礎完成
C08

Result＋呈現＋監看

像研究檔案與展示桌。 每個成果有 resultId，可分流到主地圖、表格、圖表與說明；未來還要能跨 session 保存、比較、撤回與監看。
session 版

持續監看

永遠分開看五種健康狀態

「網站打得開」不等於分析可信

一份資料可能已過期；一個工具可能能執行卻用錯 grain；一個結果可能在後端成功但沒有正確畫到地圖。這五盞燈必須分開。

目前完成的是監看規格與這個視覺入口，還不是自動監控服務。

最重要的原則：資料之間不是「能疊圖」就等於「能下結論」。

學校點位可以告訴我們學校在哪裡，但不能單獨證明學生人流、安全、健康、教育品質或環境清幽。

Observed／來源紀錄來源直接提供的紀錄或主張，仍受來源品質限制。
Derived／衍生指標有明確公式和版本、可以重新計算的結果，例如直線距離。
Proxy／替代觀察沒有直接資料時採用的近似值，必須揭露精度和限制。
Hypothesis／待驗假設合理但尚未證實的推論；缺證據時必須保留為假設或拒絕回答。

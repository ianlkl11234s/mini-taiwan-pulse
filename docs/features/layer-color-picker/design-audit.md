# 圖層配色可選：設計系統稽核與台／日面板盤點

> 2026-10-03。對象：原型 `proto/layer-color`（ef5b89b6）的 `LayerColorPicker`、`LayerColorConflictHint`、`src/map/palettes.ts`。
> 選擇頁：[`picks.html`](./picks.html)。範圍依使用者 2026-10-03 指示縮小為**熱區與網格的序列色階**；點、面、類別圖層不做。
> 證據：agent-browser 截圖（3752 原型，1440×900，暗／淡）、computed style 量測、`designSystemGuard` 測試、dataviz `validate_palette.js`。

## 0. 白話摘要

1. **台灣、日本面板用同一套元件和 CSS**，字級、顏色、間距量起來完全一樣。看起來不一樣，是因為**內容和順序**不同：日本主題列沒有英文副標、沒有大分類標籤；圖層名是中＋日文，常換兩行；最關鍵的是「顏色」列的位置不固定（台灣消防栓在第 2 列，日本宗教設施在第 1 列），而且原型裡日本那層是類別色（三個色塊），台灣是色條，所以同一個控制項兩邊長得不同。
2. **原型 §8 稽核**：自動 guard 15/15 通過，但人工檢查有 5 項不通過：選項用文字「✓」當圖示、英文小字樣式套在中文「識別色」上、清單項目沒有 2px 焦點外框、提示卡按鈕不是 C2 規格、**清單往下展開時被面板底緣裁掉**（截圖可見）。另外色盤按鈕是自製的類 select，規格 §5.9 只有原生 select，要新增元件條目。
3. **現行熱區色（G-2 magma）在兩種底圖都沒過驗證器**：暗底最低端 `#5a1977` 對比 1.33:1，淡底最高端 `#fcfdbf` 對比 1.04:1（淡色底圖上最密的地方幾乎看不見，截圖可見）。這個問題與要不要開放換色無關，預設色本身就該修。
4. **範圍內圖層**：熱區 45 層（台灣 36、日本 8、全球 1），網格 28 個 key（台灣 15、日本 13）。其中 2 個熱區、3 個網格（另加都市紋理網格的發散模式）是語意分級或發散色，不開放換色。
5. **新色盤庫**：7 階、暗淡兩版、淡色版**方向反轉**（暗底「密＝亮」、淡底「密＝深」），20 組全部通過驗證器（多色相的 viridis／cividis「單一色相」一項標 N/A）。inferno 雖然通過，但和 magma 平均只差 ΔE 5–6，兩層同時開分不出來，所以不收。

## 4. 色盤驗證

- 驗證器：dataviz `validate_palette.js --ordinal`（亮度單調、相鄰 ΔL ≥ 0.06、淺端對比 ≥ 2:1、單一色相 ≤ 40°）。
- 底圖陸地色：暗 `#262626`、`#1f1f1f`；淡 `#f5f5f3`、`#ffffff`（沿用 `palette-validation.md`）。
- 只驗**不透明的 7 階**；熱區低密度的透明淡入段不進驗證器。
- **淡色版方向反轉**：暗底「低＝暗、高＝亮」，淡底「低＝淺、高＝深」。兩版都讓低密度融進底圖、最密處最顯眼。這是「同一色盤在兩種底圖都看得見」的前提；現行 magma 兩版同值，淡底最密處是淡黃，因此失效。
- 產生方式：科學色階取 matplotlib 錨點，依 OKLab 亮度等距取 7 階（暗 L 0.47–0.95、淡 L 0.72–0.30）；單色色階固定 OKLCH 色相、色度中段最高、超出 sRGB 時降色度不改色相。
- 多色相科學色階（viridis、cividis）的「單一色相」一項標 **N/A**（設計上就是多色相，沿用 `palette-validation.md` 做法）。

# 圖層配色可選（R7 提案）

> 狀態：⏳ 提案中（2026-10-03；六題已決定，見 §0）。起因：R5（#498）熱區全站共用 magma，多層同時開分不出來；使用者希望像 kepler.gl「Dynamic Color」一樣，必要時手動換成其他科學色盤做對比。
> 樣稿：[`mockup.html`](./mockup.html)。相關規格：[`map-layers.md`](../../design-system/map-layers.md) §3.4 G-2、§3.7 K-1～K-3。


## 0. 使用者決定（2026-10-03，選擇頁 [`picks.html`](./picks.html)）

**範圍縮小**：只有**熱區**與**網格**圖層提供換色（其他點／面／類別層不做），色盤因此只需序列色階。以下各節中單色 12 色相清單、類別色組、「自動錯開」等，改為服務熱區／網格。

| 題 | 決定 | 補充 |
|---|---|---|
| Q1 入口與收合 | A：設定裡一列色條，點開清單（清單改浮出，修裁切） | |
| Q2 清單呈現 | A：長清單（kepler 式） | |
| Q3 色盤庫 | C：科學色階＋識別色衍生色階兩區 | **要更多科學色階，特別是非單色（多色相）的選項** → 另做色階總覽讓使用者挑 |
| Q4 預設色 | A：全部維持 magma（改用通過驗證的新版） | 現行 magma 四種底圖都沒過驗證器，必修 |
| Q5 台日統一範圍 | C：面板整體統一 | **很重要：連同統計與世界圖層，理論上所有 layers 的設定面板都要統一** → 獨立一輪（盤點＋選擇頁） |
| Q6 熱區疊放 | B：多層熱區同時開時各自降透明度 | |

### 0.1 色盤庫收錄（2026-10-03，[`ramp-gallery.html`](./ramp-gallery.html)）

使用者勾選 17 組：magma、rocket、YlOrBr、bilbao、turku、BuPu、Burg、acton、PuBu、oslo、tokyo、speed、viridis、cividis、YlGnBu、PuBuGn、batlow（建議 12 組全收，另加 cividis、rocket、PuBu、oslo、turku）。使用者接受其中有彼此太像的組合（例：PuBu／oslo、magma／rocket）；清單排序時把相近的分開放，並在清單上不另標警告（待確認）。
- cividis 收錄 → 「公司年齡結構」網格不必換。
- YlOrRd 未收錄 → 「不動產總市值」「預售熱力圖」「日本人口 1km」三個網格要改用庫內色階（建議 YlOrBr，最接近）。

## 1. 要解決什麼

- 多數時候不換色：每層維持設計系統給的預設色。
- 多主題同時開時，使用者要能把某層換成另一組科學色盤，讓圖層彼此分得開。
- 換一次，地圖（點、熱區、面）、圖例、側欄色點一起變；存場景時跟著存。
- 不給自由取色器：只能從驗證過暗／淡兩版的色盤庫挑，品質由色盤庫守住。

## 2. 使用者看到的樣子

1. **圖層設定**：透明度滑桿上方多一列「顏色」，顯示目前色條。點開是 kepler 式清單，只列出**這層資料類型合用**的色盤；另有「反轉」（只對序列色）與「還原預設」。
2. **依資料類型過濾清單**：

| 類型 | 例 | 清單內容 | 熱區 |
|---|---|---|---|
| 單色 `single` | 消防栓、AED | 約 12 個色相（每個色相帶一條衍生熱區色階預覽） | 由該色相衍生：透明 → 色相 → 暗色版提亮／淡色版加深（白底上提亮會消失） |
| 序列 `sequential` | 統計面、網格、密度 | 單一色相淺→深（Blues、Greens…）＋ viridis 家族 | — |
| 發散 `diverging` | 行道樹增減、人口增減 | 兩色＋中性灰中點（PuOr、RdBu…） | — |
| 類別 `categorical` | 宗教別、汙染類型 | 固定順序類別色組，**色數 ≥ 類別數者才列出** | 用該層代表色（§5.3） |

3. **多層提示**：同時開的圖層若生效色太近（§5.4），在「已開圖層」列出「消防栓 與 AED 顏色相近」，提供一鍵「自動錯開」。
4. **Agent**：可說「把這兩層分開顏色」，走既有圖層控制工具。

## 3. 架構（建議）

### 3.1 新的參數型別 `palette`

在 `layerParamsSpec` 加第五種控制項 `palette`（字串值，例如 `"hue:teal"`、`"seq:viridis"`，另帶 `reversed`）。理由：spec 已同時驅動側欄 UI、場景存檔（已存字串）、Agent 白名單與 manifest `kinds` 測試；另做一個 store 要把這四處重寫一遍。

- **不進 `encodeKeyOverlay`**：現行 overlayParams 只收數字，色盤若編成 index 會跟 select 一樣容易錯位。`palette` 另走解析器。
- 要改的地方（調查結果）：`layerParamsSpec.ts` 聯集型別、`layerParamsControls.ts` `buildParamControls`／`ParamControl`、`LayerParamControls.tsx` `renderControl`、`layerManifest.ts` `params.kinds`、`research/layerControls.ts` `kind()`／`validate()`、`memberSceneAdapter.ts` `validParam`。

### 3.2 顏色解析器

```
resolveLayerColors(layerKey, isDark) → { role, primary, ramp[], categories[], heatmapRamp[] }
```

- registry：`paint(isDark, p, colors?)` 加可選第三參數（既有 paint 不受影響）；hook：讀同一解析器。
- 圖例、側欄色點、熱區（`heatmapPaint` 改收 ramp）都讀解析器，不再各自 import 常數。

### 3.3 逐層 opt-in

`overlayRegistry.ts` 目前硬寫約 738 個 hex＋128 個 rgba，沒有單一替換點。**只有改成讀解析器的圖層才顯示顏色選單**；未遷移的層照舊、不顯示選單。每一階段明列可選色的圖層清單，不宣稱全站可換。

### 3.4 規格修訂（前提）

- **K-1 改寫**：「單色圖層 paint 主色＝識別色」改成「**識別色＝目前生效色**」；預設生效色＝現行識別色，使用者換色後側欄、圖例、地圖一起換。
- **G-2 改寫**：熱區色階由「全站 magma」改成「由該層生效色衍生」；magma 留在色盤庫供選。
- **K-3 不變**：狀態色與災害語意色（即時綠、警告橘、錯誤紅）不進一般色盤庫。

## 4. 色盤庫

- 位置：pulse 自有 `src/map/palettes.ts`（新檔）。名稱對齊分析結果的 `viz-spec.json`（viridis、magma、blue、amber、diverging、7 色類別），但 `viz-spec.json` 是 MCP repo 的副本、不能在這裡改：先在 pulse 定義，日後照「上游先動」搬回 MCP 共用。
- 來源：沿用 ColorBrewer、viridis 家族等的**名稱與色相**，色值為了在兩種底圖都通過驗證而重新取（樣稿調了 5 處，見 [`palette-validation.md`](./palette-validation.md)）。
- **每組都要暗／淡兩版、階數相同**，用 dataviz 的 `validate_palette.js` 對**兩種底圖的陸地色**驗證（亮度帶、彩度下限、相鄰色 CVD ΔE、正常視覺下限、對比）。驗不過的不收。
- 單色色相組（約 12 個）同時產出：點色（暗／淡）＋熱區色階（透明 → 色相 → 提亮）。

## 5. 規則細節

1. **預設不變**：沒換色的層看起來與現在完全相同（R5 熱區除外，見 §6 階段 1）。
   - ⚠️ 樣稿發現**現行預設色本身就有衝突**：消防栓 vs 診所 ΔE 4.7、AED vs 日本宗教設施（佛教）14.0，一開就提示；AED `#fdd835` 超出暗色亮度帶、淡色底圖幾乎看不見。階段 1 要決定是否順手修這幾層的預設色。
2. **反轉**只給序列色；發散色反轉會改變語意，不提供。
3. **類別層的熱區代表色**：用該層**筆數最多的類別**的顏色，圖例熱區列註明「以 X 類顏色表示」。
4. **「顏色相近」判定**：同時可見的點圖層，兩兩比較生效色的 OKLab ΔE（×100），**類別圖層的每個類別色都參與比較**（拉近後每類都看得到）；**< 15 提示**（dataviz 的正常視覺下限）。「自動錯開」照 12 色相的**固定順序**依序分配，只替單色圖層換色、類別圖層保持原色、未衝突的層不動；色組用完不再生成新色，改提示「建議減少同時開的圖層」。12 色相只保證順序相鄰與前 3 色兩兩分得開，同時 4 層以上不保證。
   - **熱區另驗**：點色過 15 的組合，熱區疊在一起仍可能分不出（樣稿：琥珀 vs 佛教）；熱區比較需另訂門檻（待定）。
   - **面圖層**暫不參與比較（面多半不疊著看），階段 2 再定。
5. **存檔與分享**：場景存檔（`memberSceneAdapter`）已存字串，階段 1 即支援。主站 URL 目前忽略 `p.*`、且只收數字，**分享連結要等階段 4 重新設計**。
6. **Agent**：前端白名單即 spec，加 `palette` 後自動可設；MCP 端（`mini-pulse-gis-mcp` `server.ts`）工具說明寫死四種控制項，要跨 repo 一起改。

## 6. 分階段

| 階段 | 範圍 | 為什麼這個順序 | 主要工作 |
|---|---|---|---|
| **1** | R5 的 44 個密集點圖層（點＋熱區） | 正是「熱區都一樣」與多主題對比的痛點；`heatmapPaint` 已集中，熱區改 ramp 一處生效 | `palette` 型別、解析器、色盤庫 v1（單色 12 色相）、K-1／G-2 修訂、44 層點色改讀解析器、「顏色相近」提示 |
| 2 | 統計圖層（約 320 層，共用一個 renderer） | 一個 renderer 改完全部生效、成本最低；已用 ColorBrewer | 序列／發散色盤、反轉 |
| 3 | 其餘單色與類別圖層，依圖層家族逐批 | 硬寫色最多、要逐層遷移 | 類別色組、代表色規則 |
| 4 | 分享連結＋Agent 跨 repo | 主站 URL 參數要重新設計；MCP 工具說明要改 | URL 字串參數、MCP 說明 |

不在範圍：Three.js 圖層（約 15 層，另有 R6 Three.js／Mapbox 切換議題）。

## 7. 待使用者決定

1. **階段 1 先做哪一塊**：建議 R5 的 44 層（直接解決對比需求）；另一個選項是統計圖層（成本最低，但統計面很少疊著看）。
2. **R5 熱區預設色**：階段 1 上線後，44 層熱區預設改成各層識別色衍生（拉近換點時顏色連續），magma 退為可選。或維持 magma 為預設、只在使用者換色時改。
3. **單色色相數量**：建議 12 個；多了清單長、相鄰色相難分。
5. **序列色暗／淡方向**：樣稿讓低值都融進底圖（暗版低值偏暗、淡版低值偏淺），與現行統計層「暗／淡同色值」不同；階段 2 前要決定。
6. **現行預設色衝突**（§5.1）：階段 1 要不要順手修消防栓／診所／AED 的預設色。
4. **「顏色相近」提示**：只提示（建議），或偵測到就自動錯開。

## 8. 風險

- 硬寫色約 866 處，逐層遷移是主要成本；每階段只承諾清單內的層。
- 色盤階數在暗／淡切換時不能變，否則圖例與分級錯位。
- 圖例 `LegendPanel.tsx` 約 6.3k 行手寫，每層遷移時要一起改讀解析器。
- 換色後 R4 建立的「圖例與地圖同源」測試要改成驗「同一解析器」。

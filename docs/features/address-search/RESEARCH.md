# 地址／地名搜尋：服務比較與建議（GUI-3 研究）

> 日期：2026-11-21。只研究、不實作。需站主拍板：**D1 選服務**、**D2 搜尋框位置**。
> 現況：圖層搜尋已有（`src/lib/layerSearch.ts`）；`IconRailSidebar` 的「Search locations...」只篩選預設城市書籤（`src/lib/locationSearch.ts`），不是地址查詢。

## 1. 一句話建議

**第一階段用「自建本地索引」（鄉鎮市區、村里、車站、已有 POI 的名稱）做地名搜尋，不需金鑰、不需部署、全站可用；門牌地址另加「可選的外部服務」當第二階段**，外部服務建議 Mapbox Geocoding（金鑰可用 URL 限制的公開 token，不必 Worker 代理），但只做「查完就飛過去」，不儲存結果。

理由：本站使用者最常打的是地名、車站、縣市、村里，本地索引就能命中，且 0 成本、0 延遲、不外送使用者輸入；門牌地址在三個免金鑰實測來源都命中不了，要靠有金鑰的服務。

## 3. 實測（20 筆，台灣）

**範圍與限制**：只測不需金鑰的服務。Mapbox、TGOS 需金鑰，`pulse-secret-run` 的 `api-probe` 沒有這兩個來源，且依規定不讀金鑰檔，故**未實測**。另加 OpenStreetMap Nominatim 作為「免金鑰全球地名服務」的參照（公開服務條款限制大量使用，只能當參照，不建議正式採用）。NLSC 測的是 `api.nlsc.gov.tw/MapSearch/QuerySearch`（官網地圖搜尋用的端點，需帶 Referer，**未公開文件**）。測試時間 2026-11-21，查詢不含任何個資（皆為公共機關或地標）。

## 4. 金鑰走 Worker 代理是否需要部署

- **Mapbox**：不需要。公開 token 本來就放前端，在 Mapbox 後台限制允許網域即可。若站主希望隱藏用量／防濫用，才加 Worker 代理（需站主同意部署）。
- **TGOS**：需要。金鑰不可進 bundle，須走 Cloudflare Worker 或 research-gateway 代理，並加速率限制；部署需站主同意。
- **NLSC**：不建議採用。
- **自建索引**：不需要。純前端載入靜態 JSON／PMTiles。

## 5. 推薦方案

1. **第一階段（建議先做）**：本地索引。來源＝縣市／鄉鎮代表點（已有）＋村里＋車站＋既有 POI 名稱；沿用 `locationSearch.ts` 的正規化（臺／台、全形）；結果與圖層搜尋分兩區；查不到顯示「找不到」。外國依目前國家只查該國索引。
2. **第二階段（站主同意再做）**：加 Mapbox Geocoding 當「門牌地址／找不到時的備援」。限制：只用暫時性結果、不儲存；使用者輸入要告知會送到 Mapbox；僅在使用者按下搜尋或停頓後才呼叫，節省額度；先在 Mapbox 後台確認免費額度與計費上限。
3. **不採用**：NLSC 未公開端點（實測無用且無服務承諾）；TGOS 即時查詢（需代理與部署，且只涵蓋台灣，除非站主要求更高門牌精準度）。

主要風險：Mapbox 對台灣門牌的命中率本次**未實測**，第二階段開工前應由站主提供一支限制網域的測試 token，或站主同意後以 20 題重測。

## 6. D2 搜尋框位置：3 個候選

- **A. 併入既有側欄「Search locations...」**：改成同時搜地點與圖層，結果分「地點」「圖層」兩區。改動最小、入口不增加；缺點是搜尋框藏在側欄，收合時看不到，手機尤其不顯眼。
- **B. 地圖左上獨立搜尋框**：像 Google Maps，永遠可見，查完直接飛過去並放暫時標記。最直覺；缺點是要避開左上既有控制項與圖例，需要調整版面與 design-system 檢查。
- **C. 與圖層搜尋合一（單一萬用搜尋框）**：一個框打什麼都行，下方分「地點」「圖層」兩區。入口最少、最像 Spotlight；缺點是使用者打「公車」時，不知道是要找圖層還是找地名，結果區要設計好排序，且 `LayersPanel` 的圖層搜尋要整合。

建議：先做 C 或 A 的資料層（同一套搜尋邏輯），外觀由站主看預覽圖後定；B 若站主偏好「像地圖 App」再選。

## 7. 給站主的決定題

- **D1 選服務**：(a) 只做本地索引；(b) 本地索引＋Mapbox 備援（建議）；(c) 本地索引＋TGOS（需 Worker 代理與部署）。
- **D2 搜尋框位置**：A 併入側欄、B 地圖左上獨立、C 與圖層搜尋合一。

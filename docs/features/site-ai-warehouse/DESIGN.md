## 0. 給站主的三句話

1. 現在網站上的 AI 對話框只會開圖層、查少數幾份靜態檔和 10 支固定查詢；**真正能算排名、熱點、交叉分析的「分析倉庫」只有站主本機的 Claude Code 用得到**。
2. 要讓訪客也用得到，最穩的做法是：**在伺服器上開一個「只回答固定題型」的倉庫查詢服務，網站上的 AI 呼叫它**（路線 a），先只開給站主，再開給登入會員。
3. 開給站主以外的人之前，**一定要先把 18 張站主限定資料搬出公開版倉庫**（OWNV-1），以及決定「AI 的費用誰付」。這兩件事要站主拍板，題目在 §9。

## 1. 現況

### 1.1 網站上的 AI（BYOK 對話框）能做什麼

- 訪客自己填 Anthropic／OpenAI／Google 的金鑰，AI **直接在訪客的瀏覽器裡跑**，金鑰不經過我們的伺服器（`src/chat/providers.ts`）。
- 能用的工具（`src/chat/tools/registry.ts`）：
  - 找圖層、讀圖層說明（catalog）；
  - 開關圖層、飛到某地、在地圖上標點（map）；
  - 查 20 份白名單靜態 GeoJSON 的筆數與篩選、H3 人口排名（data）；
  - 呼叫 10 支白名單 Supabase 查詢（`src/chat/tools/rpcTools.ts`）。
- 一題最多 10 步工具呼叫（`src/chat/agent.ts`）。

### 1.2 它不能做什麼

- **不能讀分析倉庫**：`src/chat` 裡沒有任何倉庫相關程式。倉庫有 700 多份資料、統計長表 100 萬筆以上；BYOK 只摸得到其中 20 份靜態檔。
- 不能做縣市／鄉鎮排名、人均、熱點（Gi\*、LISA）、兩份資料的交叉比對、等時圈。
- 回答沒有固定附「資料日期、涵蓋範圍、來源」。

### 1.3 站主本機的 AI 為什麼比較強

- 路徑：Claude Code → 本機 MCP `pulse-research`（core 23 工具）→ 本機 DuckDB **唯讀**開倉庫（約 6 GB，R2 私有 bucket `pulse-warehouse`，下載到本機快取）→ 結果經 research-gateway 畫到站主已登入的地圖分頁。說明書：[agent-research-workbench/ARCHITECTURE.md](../agent-research-workbench/ARCHITECTURE.md)。
- 計算都在站主的 Mac 上；Mac 沒開就不能分析，這是 ADR-0017 刻意的取捨。
- research-gateway 只做身分驗證（Supabase 登入＋試辦帳號 allowlist）、指令轉送與限流，**不讀資料、不跑查詢**。
- 前端的 Agent 面板目前只開給站主：`App.tsx` 的 `agentEnabled = import.meta.env.DEV || isOwner`。

### 1.4 擋路的事

| ID | 問題 | 影響 |
|---|---|---|
| OWNV-1 | 倉庫裡有 18 張站主限定表；目錄的 `visibility` 欄 713 列全寫 `owner`，分不出哪些能公開。查詢引擎（`mini-pulse-gis-mcp/src/warehouse/engine.ts`）只讀出這個欄位，**沒有用它擋查詢**（只查了這個檔）。 | 開放給站主以外的人之前一定要解決 |
| FB-023 | BYOK 預設模型待決 | 影響費用與答題品質 |
| MCPD-2 | 結果檔 `wh-N` 跨 session 互相覆寫 | 多人同時用時一定會出事 |
| VIZ-20、FB-157 | Agent 不能設比較模式；分析卡缺比較、等時圈、村里 | 功能缺口，不擋開放 |

## 2. 兩個獨立的選擇

站主要決定兩件**彼此獨立**的事，可以自由組合：

| 軸 | 問題 | 選項 |
|---|---|---|
| **A. 查詢在哪裡跑**（架構路線） | 倉庫查詢由誰執行 | (a) 伺服器上的唯讀查詢 API／(b) MCP App，在訪客自己的 Claude／ChatGPT 裡用／(c) 訪客瀏覽器直接讀倉庫檔（DuckDB-WASM） |
| **B. AI 的費用誰付**（費用模式） | LLM 的 token 費 | 訪客自備金鑰（現狀）／站方出額度＋每日配額／只走 MCP App（訪客用自己的訂閱） |

注意：**選「站方出額度」就一定要有伺服器端代理**替訪客呼叫 LLM。這會推翻現在「金鑰零經手、不做 proxy」的承諾，隱私頁也要改寫。

## 3. 架構路線比較

### (a) 伺服器上的倉庫唯讀查詢 API（推薦）

**做法**：在伺服器上跑一個查詢服務，載入「公開版倉庫」，只提供參數化的固定題型（找資料、排名、附近、空間統計、交叉分析），網站上的 AI 透過新工具呼叫它，結果照現在的方式畫在地圖上。

- **使用者體驗**：在網站對話框直接問，答案畫在同一張地圖上。冷快取第一題可能要十幾秒（2026-09-26 實測冷快取首題 19 秒、熱快取同本機），之後與站主本機相近。
- **要部署什麼**：
  1. 查詢服務（可沿用 MCP 的 `WarehouseEngine`，包成 HTTP）；
  2. 一份**不含站主限定表**的公開版倉庫（見 §5）；
  3. Worker `/api/*` 已經會轉到 pulse-host（`deploy/cloudflare/src/worker.js`），可沿用；
  4. 網站 `src/chat/tools/` 新增倉庫工具。
- **安全風險與對策**：
  - **SQL 注入**：BYOK 時 AI 在訪客瀏覽器裡跑，工具呼叫完全由訪客控制，**每個請求都要當成惡意**，AI 不是安全邊界。現有的 SQL 守門（只准 SELECT、禁關鍵字與讀檔函式、DuckDB 唯讀＋關閉外部存取）是為「單一可信使用者」設計的。對策：對外**只開參數化工具**，伺服器自己組 SQL；自由 SQL 只給站主。
  - **資源濫用**：大範圍空間 join 可能吃滿 CPU／記憶體。對策：每次查詢逾時（現為 20 秒，對外建議更短）、單次回傳筆數上限、每帳號／每 IP 限流、同時查詢數上限、查詢服務與 collector 分開資源（容器記憶體上限）。
  - **站主限定資料外洩**：靠「公開版倉庫實體上不含這些表」，不靠執行時過濾。
- **每月成本（估算）**：
  - 主機：倉庫約 5.98 GB（2026-10-17 版，之後未重量），pulse-host 是 4GB 且同機跑 collector、valhalla。**放不放得下未量測**；若要另開一台，費用依 Linode 官網價目為準（**待查**）。
  - 流量：R2 沒有出站費；Worker 轉發走既有方案。
  - LLM 費用另計，見 §4。
- **延遲**：熱快取每題數秒～十幾秒（主要是 LLM 多步思考）；查詢本身多數 <1.5 秒（例：臺北市 Gi\* 332 格 <1.5 秒，見 ARCHITECTURE 的配方表）。
- **維護成本**：中。多一個常駐服務要監控；倉庫每次組裝要同步產公開版。
- **工作量**：中（約 2–3 週，含公開版倉庫、查詢服務、前端工具、限流、評測）。

### (b) MCP App：訪客在自己的 Claude／ChatGPT 裡用

**做法**：把倉庫工具包成遠端 MCP 伺服器（加上 MCP App 介面，地圖嵌在對話裡）。訪客在自己的 Claude 或 ChatGPT 加入這個連接器。HANDOFF 列的參考：Mapbox MCP Apps、CARTO for Agents、Felt MCP（本文件未逐一查證其產品細節）。

- **使用者體驗**：不在我們的網站上問，而是在訪客自己的 AI 對話裡；地圖是嵌在對話裡的小地圖，不是完整的 Pulse 圖台。適合重度使用者。
- **要部署什麼**：遠端 MCP 伺服器（同樣需要伺服器上的查詢引擎與公開版倉庫）、OAuth 登入、嵌入式地圖介面。
- **安全風險**：與 (a) 相同（查詢同樣在我們的伺服器跑），而且呼叫者是外部 AI，更要只開參數化工具。另要處理 OAuth 與連接器審核。
- **每月成本（估算）**：主機同 (a)；**LLM 費用由訪客的訂閱付，站方 0**。
- **延遲**：同 (a)，再加上對方平台的往返。
- **維護成本**：高。要跟著 MCP Apps 規格與各平台的連接器規則改；嵌入式地圖要另做一套。
- **工作量**：大（約 4–6 週）。而且它**需要 (a) 的查詢服務當底**，所以實際上是 (a) 之後的延伸。

### (c) 瀏覽器直接讀倉庫檔（DuckDB-WASM）

**做法**：訪客瀏覽器載入 DuckDB-WASM，直接從 R2 讀倉庫的 Parquet 檔來算。

- **前提目前不成立**：ADR-0026 寫明 `pulse-warehouse` 是**私有** bucket，沒有「公開倉庫檔」。要先產一份公開子集放到公開 R2。
- **使用者體驗**：第一次要下載資料（每題可能數十～數百 MB），手機與慢網路很吃力；熱的時候很快。
- **要部署什麼**：公開子集倉庫、前端 DuckDB-WASM（套件數 MB）。DuckDB-WASM 能否跑 spatial 擴充與 EPSG:3826 轉換**需 PoC**。
- **安全風險**：查詢在訪客自己的電腦跑，沒有伺服器資源濫用問題；SQL 注入也只影響他自己。但**公開子集裡的每一筆都等於公開下載**，授權與個資審查要比 (a) 嚴（(a) 只回彙總結果）。
- **每月成本（估算）**：沒有伺服器；R2 儲存與讀取次數費用（價目**待查**，以 Cloudflare 官網為準）。
- **延遲**：冷啟動慢（下載），熱的時候快。
- **維護成本**：中。公開子集要隨倉庫更新；前端 bundle 變大。
- **工作量**：中～大（約 3–4 週，含 PoC）。

### 3.1 一表比較

| 項目 | (a) 伺服器查詢 API | (b) MCP App | (c) 瀏覽器 DuckDB-WASM |
|---|---|---|---|
| 在哪裡問 | 網站對話框 | 訪客自己的 Claude／ChatGPT | 網站對話框 |
| 完整圖台 | 有 | 沒有（嵌入小地圖） | 有 |
| 站方 LLM 費 | 看費用模式 | 0 | 看費用模式 |
| 站方主機費 | 有（容量未量測） | 有（同 a） | 幾乎沒有 |
| SQL 注入／濫用 | 要做參數化＋限流 | 同 a | 只影響訪客自己 |
| 站主資料外洩 | 公開版倉庫不含即可 | 同 a | 公開子集＝公開下載，審查最嚴 |
| 手機體驗 | 好 | 看平台 | 差（要下載資料） |
| 工作量 | 中 | 大（且要先有 a） | 中～大（含 PoC） |

## 4. 費用模式

### 4.1 三種模式

| 模式 | 說明 | 站方 LLM 費 | 優點 | 缺點 |
|---|---|---|---|---|
| **訪客自備金鑰（現狀）** | 訪客填自己的金鑰 | 0 | 不用改隱私承諾、沒有被刷爆的風險 | 一般訪客沒有金鑰，實際用的人很少 |
| **站方出額度＋每日配額** | 站方的金鑰，經伺服器代理呼叫 | 有，可用配額封頂 | 一般訪客也能用 | 要做代理、配額、濫用防護；隱私頁要改；金鑰在伺服器 |
| **只走 MCP App** | 訪客用自己的 Claude／ChatGPT 訂閱 | 0 | 站方不付 LLM 費 | 只有付費 AI 訂閱的人用得到；體驗不在 Pulse 圖台 |

### 4.2 每題 LLM 費用估算

**公式**：每題費用 ≈（未快取輸入 token × 輸入單價）＋（快取命中 token × 快取讀取單價）＋（輸出 token × 輸出單價）。每月費用 ≈ 每題費用 × 每日題數 × 30。

**單價**（Anthropic 官方 API，claude-api skill 價目表，快取日期 2026-11-03；每百萬 token，美元）：

| 模型 | 輸入 | 輸出 | 快取讀取 |
|---|---|---|---|
| Claude Haiku 5.5 | 0.10 | 0.50 | 約輸入的 1/10 |
| Claude Sonnet 5.5 | 2.00 | 10.00 | 0.10 |
| Claude Opus 5.5 | 4.00 | 20.00 | 0.20 |

**假設**（估算，未實測）：一題倉庫分析約 8 步工具呼叫，系統提示＋工具定義約 1.5 萬 token；每步重送對話，總輸入約 20 萬 token，其中約 90% 命中快取；輸出約 3,000 token。

| 模型 | 每題約 | 每天 100 題的每月約 |
|---|---|---|
| Haiku 5.5 | US$0.005 | US$15 |
| Sonnet 5.5 | US$0.09 | US$270 |
| Opus 5.5 | US$0.18 | US$540 |

**上限參考（實測）**：站主本機 eval 用 Claude Code＋sonnet 每題約 US$0.3–1.8（ARCHITECTURE §7；那是完整 Claude Code session，提示與步驟比網站版重很多）。網站版的實際數字要在第 1 階段量測後更新。

**結論**：站方出額度時，**每日配額比模型選擇更重要**。例：每日總預算 US$5 封頂、每位會員每天 5 題、Sonnet 5.5，最壞每月約 US$150；超過就當天停用並顯示「今日額度用完」。

## 5. OWNV-1：開放前一定要做的資料隔離

建議用**實體隔離**，不靠執行時過濾：另外組裝一份「公開版倉庫」，裡面根本沒有站主限定表。這樣就算查詢服務有漏洞，也拿不到不存在的資料。

步驟：

1. **寫真值**：在 pulse-data registry 每份資料的 `warehouse:` 區塊標 `visibility: public|owner`，來源對照現有站主限定清單（`public.gated_layers`、layer-status 的 DISPLAY_ONLY／站主限定）。組裝時把它寫進 `wh_catalog.visibility`，不再全部預設 `owner`。
2. **組兩份**：`assemble_store` 產「完整版」（站主本機 MCP 用）與「公開版」（只含 `public`）。公開版另做檢查：目錄裡不得出現任何 `owner`，表數＝public 數。
3. **儲存分開**：完整版維持私有 bucket；站主資料包移到另一個私有前綴或 bucket，公開版服務的讀取權限碰不到它。
4. **引擎也擋**（第二道防線）：查詢服務依身分只掛載對應版本；非站主的請求，就算指定表名也回「查無此資料」。
5. **驗收**：用非站主身分跑一組題目，18 張表全部查不到；公開版資料包不在可公開存取的位置。

> 本文件不列 18 張表的表名（本 repo 公開）。清單以 BACKLOG OWNV-1 與 registry 為準。

**授權另一層**：ADR-0014 寫「僅本人使用不受授權 HOLD 阻擋；公開發布另審」；2026-10-09 站主決定 HOLD 資料「入倉即放行」。但「放行」是針對地圖顯示與站主分析，**把彙總結果給任意訪客算不算「公開發布」，沒有明文**，列為決定題 Q4。

## 6. 可信度呈現與評測

### 6.1 每個答案固定附

沿用 pulse-conductor skill 的回答規則：

- **資料日期**（倉庫版本與該資料的最後更新日）、**涵蓋範圍**（縣市／國家）、**來源**（機關名稱）；由查詢服務在結果中回傳，前端固定顯示成一行小字，不靠 AI 自己記得寫。
- **未涵蓋不畫成 0**：沒資料的區域在地圖上用斜線／灰色，文字寫「未涵蓋」。
- 不露出內部代號（表名、欄位名、`wh-N`）。
- 一題只附一句技術但書；位置精度（地址定位、村里中心點等）照 L3 屬性加註。

### 6.2 評測接 CI

- **沿用既有題庫**：MCP repo `eval/agent-regression/`（主題庫 30 題、分層 13 題、查證 8 題、空間統計 20 題），答案都用唯讀 SQL 驗算過。
- **兩層做法**（參考 HANDOFF 列的 WRI project-zeno GOLD 回歸測試思路）：
  1. **每個 PR 跑、免費**：對查詢服務的參數化工具直接打題庫的「標準呼叫」，比對數字與驗算 SQL（不經 LLM，結果固定）。另跑「站主表查不到」與「惡意參數被擋」的安全題。
  2. **每週或發版前、付費**：用網站版 agent（固定模型）跑一小組題（例如 10 題），記錄分數與每題費用；分數掉超過門檻就擋發版。費用估算見 §4.2。
- 現行 eval 不進 CI 的原因（要登入的 CLI、本機倉庫、已登入地圖分頁）在第 1 層全部消失，因為只打 HTTP 服務。

## 7. 開放範圍與額度設計

沿用既有會員機制：`profiles.tier`（free／member／insider／owner，`src/lib/auth.ts`），research-gateway 已有 Supabase 登入驗證、allowlist 與限流。

| 範圍 | 需要先完成 | 建議額度與限流（站方出額度時） | 風險 |
|---|---|---|---|
| **只站主** | 不需要 OWNV-1（站主本來就能看全部） | 不設配額，只設單次逾時 | 最低 |
| **登入會員**（member／insider） | OWNV-1、公開版倉庫、配額 | 每人每天 5–10 題、每分鐘 2 題；全站每日預算封頂；insider 可加倍 | 中：帳號可大量註冊，要配 email 驗證與全站封頂 |
| **所有訪客** | 上面全部＋防機器人（Cloudflare Turnstile 等） | 每 IP 每天 2–3 題；全站每日預算封頂；只開最便宜模型 | 高：濫用與費用最難控 |

不論範圍，**自備金鑰模式**都只需要限制「查詢服務」的用量（每帳號／IP 每分鐘查詢數、同時查詢數），不必限制 LLM。

## 8. 推薦方案與分階段計畫

**推薦**：路線 (a) 伺服器查詢 API＋只開參數化工具；費用先維持**訪客自備金鑰**，第 2 階段再決定要不要站方出額度給會員；(b) MCP App 等 (a) 穩定後再評估。

理由：(a) 是 (b) 的底層，也最貼近現有網站體驗；自備金鑰不必改隱私承諾、沒有被刷爆的風險；先只開站主可以不等 OWNV-1 就開始驗證。

| 階段 | 內容 | 驗收條件 |
|---|---|---|
| **0　準備**（不受拍板影響） | 修 MCPD-2（結果檔名加倉庫版本＋session id）；量測倉庫在 pulse-host 或另一台主機的記憶體與磁碟需求 | 兩個 session 各跑 wh-1，兩份結果都讀得回來；有一份容量量測報告，寫明放哪台主機 |
| **1　只站主** | 查詢服務（參數化工具 4–5 個：找資料、排名、附近、空間統計、交叉分析）；網站 BYOK 新增倉庫工具，只對 `isOwner` 開；答案固定附日期／範圍／來源 | 站主在正式站對話框問 10 題題庫題，數字與驗算 SQL 一致、都畫上地圖；每題費用與延遲有紀錄；第 1 層評測接上 CI 並綠燈 |
| **2　登入會員** | OWNV-1 完成（公開版倉庫）；限流與配額；若拍板站方出額度，做 LLM 代理與每日封頂；隱私頁更新 | 非站主帳號查不到 18 張表；超過配額回友善訊息；全站每日費用不超過拍板上限；安全題（惡意參數、超大範圍）全部被擋 |
| **3　擴大**（看拍板） | 開放所有訪客（加防機器人）或做 MCP App | 依該階段另訂；拍板前不做 |

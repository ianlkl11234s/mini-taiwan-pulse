## 刻意做的決策（可逆，請使用者確認）

- **D1 新鮮度優先於完整性**：pending queue 加 48h TTL、newest-first；過期候選只記 receipt 不送 LLM。代價：09-03 18:45 → 09-04 晚間的 backlog 大部分不會被評估，七天視圖那段會偏少。理由：目標是「看到正在發生的事」，30 小時前的新聞價值已低，且不加 TTL 佇列在路由量 > cap 時無界成長。
- **D2 不改 OpenRouter 模型**：維持 `qwen/qwen3.7-flash`；fallback 模型列表放 env（預設空）供日後開啟。
- **D4 prompt 調查結論**（提案全文在 scratchpad `prompt-proposal.md`，會隨 D1/D2 PR 收進 docs）：截圖 117 筆待定位約 105 筆是 09-03 09:00 UTC metadata fallback 上線前的舊帳，會自然滾出 7 天窗；上線後殘留 14.8%，全是 GDELT 自身無座標（69%）或只有 ADM1 層級被丟掉（31%），**沒有「GKG 有座標但沒用」的案例**，國家標錯 0 筆。低價值條目是前端沒依 decision 過濾（drop_noise 佔 34%）。prompt 本身無重要性判準、無國家欄位，模型選點率僅 51.7%。
- **D5 feed 時間語意用 `observed_at`（事件／報導時間），不用 `available_at`**：與新聞 `published_ts` 對齊；E 實測時 24h 窗 0 件是上游落後 26h 的暫時現象，用 `available_at` 會讓 30 小時前的新聞顯示「5 分鐘前」。代價：1H RANGE 在 collector 每小時一輪的節奏下天生稀疏。
- **D3 不動 `pg_default_acl`**：只對現有 VOLATILE definer 寫入函式明確 REVOKE `cloud_agent_ro`，不改 default privileges（改了會讓未來的讀 RPC 也失去 EXECUTE）。

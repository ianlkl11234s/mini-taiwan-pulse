## Context 與 token 策略（主 agent 必守）

- 主 agent 只做：拆解、派工、驗收、整合、對使用者回報；**不自己讀大檔或長 log**。
- 派工模型：已定位的執行（批次補 manifest、改測試、寫配方、跑驗證）→ **sonnet**；判斷取捨／架構（指數設計、視覺化 UI 設計、分類規則）→ 預設模型，但先由主 agent 寫清楚規格。
- 每個 worker prompt 必含：目標、cwd、可改檔案白名單、禁改清單、驗收指令、回報上限（≤500 字，長輸出寫檔給路徑）。
- 同時最多 3 個 worker；**同一 repo 同一檔案不可平行寫**。共用登記檔（`layerManifest.ts`、`layer-dataset-aliases.json`、`layer-status-overrides.json`、`categories.json`、`questionBank.ts`）由主 agent 最後統一接線。
- 背景 agent 若撞用量上限：先 `git status`／`git log` 看它留下什麼，再決定接手或重派，不重做已 commit 的部分。

## 軌道 2：擴大問題庫（主指標＝能回答的問題數）

- 題綱與分類見 [question-bank-backlog-20260927.md](./question-bank-backlog-20260927.md)（使用者 2026-09-27 提的 6 大方向＋擴充面向＋GIS 技法對照＋指數設計）。
- 做法：每題落成 `questionBank.ts` 一個 case（真實資料、PASS/PARTIAL/GAP＋gaps 說明）＋對應 `recipes/` 配方（新題型才新增配方檔）。
- 批次 1（資料已在倉庫，先做）：基礎設施周邊（發電廠／超高壓變電所 × 其他設施）、市場 × 畜牧場、生活品質六面向相對比較（台北各區 vs 全市）、學校步行涵蓋、淹水潛勢 × 房價、污染源 × 水源保護區 × 共同登記熱點、畜牧場聚集度、新聞熱點持續性、縣市教育／農業多圖層比較。
- 批次 2（需補資料或新能力）：網路等時圈（步行 10/15 分）、運動場館細分類（網球／匹克球／羽球）、中國海警船 × 新聞、地震 × 周邊設施、指數（生活品質指數）。
- 新能力（主 agent 設計、sonnet 實作）：`pulse_sql` 可用的**標準化指數模板**（z-score／百分位、權重、敏感度）；熱點**顯著性**（Getis-Ord Gi*，DuckDB 內以鄰接矩陣實作或 Python 後處理）；**邊界交叉**與**面疊合面積**配方（已有 SQL 基礎）。
- Jev（`pulse_route_request`，使用者稱 JEP）：只在題型不明時用來縮小候選；新增題型後同步更新其 capability 描述（`mcp/src/research/jevRouter.ts`）與 `references/jev-accelerator.md`，並用問題庫題目抽測路由正確率。
- 驗收：問題庫 ≥20 題、PASS 比例、每題耗時；skill 正文維持 ≤5,000 字元。

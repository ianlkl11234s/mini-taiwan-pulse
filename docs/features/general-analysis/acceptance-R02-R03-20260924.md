### 量測定義與結果

這是**同一主task逐題讀取自然語言控制題、決定工具、讀回結果、寫入答案的20次native控制問答**，不是CLI driver直接算答案，也不是20輪真實使用者對話。起點為題目建立時鐘，終點為本題答案寫入收據；包含中間模型與工具等待，未取得可分離的模型queue/thinking/provider token時間。每題完整calls與答案存在相鄰runtime `r02-C00.json`、`r02-Q01.json`至`r02-Q20.json`。Q20 search收據僅在檔中摘錄，原完整工具回覆保留於本task。

- 20題：median **25.66秒**、nearest-rank p95 **45.77秒**、max **51.97秒**；共79次頂層native MCP calls。batch內部query不是零成本，不能把79當全部Gateway子請求數。
- 固定版本期間無HMR；19題完成查詢／分析／呈現，Q20抓到discovery-only describe缺陷，原始失敗保留。修復後另測，不覆寫原樣本。
- C00頁面重載後首次學校查詢58.75秒，另列不混入20題。20題是session warm；新地點學校分片及首次其他來源仍可能cache miss，source cold/warm依每筆receipt `cacheHit/downloadedBytes/requests`分列，**不宣稱20題全來源cache warm**。
- 無參數schema錯誤、無原樣重送或pending重跑。Q20 describe一次失敗後改search辨認來源資格；不是把不可分析資料硬算成答案。
- 這組結果不關閉G01「20輪真實使用者問答SLA」；也不直接與先前不同模型／題目／來源的152／218秒做因果速度倍數比較。90秒目標於此控制樣本均未超過。

## 3. 第二主題Polygon與新設施

來源資格見[qualification](./qualification-V02-20260924.md)：雙北114筆都市計畫墓葬分區衍生面、玉山官方座標30筆子集。原始檔archive SHA鏈未取得，觀測日期未知；不擴張為原始法定界線／全國官方設施。

核心descriptor現在僅允許具有immutable SHA版本、明確precision／lineage的EPSG:4326 derived Polygon/MultiPolygon具空間分析資格。generalized/proxy、derived Point/Line、缺SHA或mutable版本維持拒絕；bbox仍只對合格Point開放，面以ID／屬性選取。contains_center與既有點面、線面、per-area操作共用相同surface資格守門。未放寬頂點／拓樸／運算預算。

Q16新面Z0001球面39179.24156m²、來源3.91ha、46頂點；Q17 Z0013球面81.73175m²、來源0.008ha、12頂點。兩者同native鏈query→measure→bounds→collection→ready→readback。Q18學校與Z0001相交0筆，邊界包含規則保留。Q10/Q11新山屋子集的範圍／最近查詢及地圖已通過，不代替步行可及性。

## 獨立核對與最終狀態

獨立 Python oracle由Luna直接讀固定source bytes，執行haversine、Shapely及pyproj/Geod，未讀native答案；完成native後主agent才讀oracle。原始oracle第一版只算nearest漏radius count，已要求更正，不能將該版冒充圈內數量驗收。最終核對採 native structured rows／summary，不靠答案文字判定。Q01–Q18 的可比欄位全部通過：圈內數量、回傳樣本名稱與距離（容忍0.001m）、來源selector排除量、學制計數、人口比例（6位小數）及差額／比值。Q01 receipt只回2筆樣本，因此該題全量5筆計數通過、名稱距離僅核對2筆，不宣稱全5筆名稱逐一驗收。Q19沒有第二份獨立官方歷史事件快照，不列oracle通過；Q20是metadata資格守門。

Z0001／Z0013球面計算與獨立Geod的相對誤差分別2.85e-7／2.23e-6，皆低於1e-5；EPSG:3826值另列39093.789577／81.549389m²，不能與球面運算混為同算法。Q18零筆且bbox候選亦為零；另以獨立Shapely representative point `[121.59512514453044,25.086433]` 呼叫contains_center，native命中Z0001，補正向資格。此補測首次誤用resultId被INPUT_INVALID攔截，改讀live schema後修為areaResultId；失敗不藏在「20題零schema錯誤」之外，已補入skill參數說明。

Q20 修補涵蓋 describeDataset 與瀏覽器先呼叫的 ensureDataset：discovery-only可說明、不能materialize，locked/unknown仍拒絕。HMR曾保留舊callback，完整reload後 native describe complete且query仍拒絕。這是修補後另測，沒有覆寫原20題。

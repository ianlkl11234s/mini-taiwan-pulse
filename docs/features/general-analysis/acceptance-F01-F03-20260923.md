## F01：為何篩不小

本次用原匿名讀取設定、既有Supabase client唯讀呼叫 `get_road_events_current`；只輸出計數/契約摘要，不輸出key或完整道路資料。參數 p_source=live_freeway、p_event_type=3、p_only_active=true、p_limit=51：1079ms，51筆全部source/type吻合，**51筆expire_time全NULL**。因此不是參數遺失；缺到期資料使未到期篩選無法排除本次這些資料。這僅描述有界樣本，不能宣稱所有來源都缺到期，也不能把NULL說成已過期。

證據：`../runtime/f01-road-transport-probe.json`。原SQL（gis-platform `migrations/124_rpc_hard_limits.sql:123`，之後312搬到live schema）只有source/type/expiry三個條件，內部先ORDER/LIMIT；外層PostgREST filter只會篩先取回的資料，可能漏掉後面匹配列，不可用作完整範圍。collector只清expire<now，NULL沒有提供撤回判斷。

前端修正 `5fe3c99d`：維持51安全邊界，同時先揭露source/type/identity契約錯誤。測試驗證真正 fetchRoadEventsCurrent 的RPC參數、caller AbortSignal、服務錯誤與缺配置；之前只有mock fetcher的測試不足以證明傳輸。最後在新版browser走原RPC仍dense是預期結果，不是成功分析。

# 2026-08-20 幾何簡化在平面空間守約，但 geography 距離把長弦當測地線 → 405 公尺誤差

**日期**：2026-08-20
**嚴重度**：medium
**受影響範圍**：Vessel Zone Watch（VZ-2）距離計算；任何「`ST_Simplify*` 換效能 ＋ `ST_Distance(::geography)` 量距離」的組合
**發現方式**：子代理精度驗收未過 → 主 agent 誤判根因 → 子代理反駁主 agent 的數字後才找到真因
**耗時**：發現 → 定案約 3 小時，走了兩條錯路

---

## 現象（Symptom）

把 24 浬界線用 `ST_SimplifyPreserveTopology` 簡化換取效能後，某案例的距離值與全解析度差
**0.157 浬（290 公尺）**。詭異的是：**把容差調到 0.00002°（546 個頂點）誤差依然不變**。

只有臺灣本島這條線有問題，東沙／釣魚台／黃岩島三條都正常（偏離 20~21 公尺）。

## 根因（Root Cause）

**Douglas-Peucker 完全守約，錯的是量距離的方式。**

| 量測 | 值 |
|---|---|
| 最差頂點到簡化線的**平面**（經緯度）距離 | **1.9 公尺** ← DP 的保證完全成立 |
| 同一頂點到簡化線的 **geography** 距離 | **405.4 公尺** |

DP 在**平面（度）空間**保證「被移除的頂點到簡化線段的垂直距離 ≤ 容差」。
但 `ST_Distance(::geography)` 把那條「在經緯度上是直線」的長線段**當成測地線（大圓）詮釋**——
兩者在長距離上分歧極大。**弦越長，分歧越大**。

簡化的本質就是把許多短線段合併成長弦 → 弦一長，平面直線與大圓線就分家。
臺灣本島的簡化結果有長弦，另外三個 region 的線較曲折、簡化後仍是短段，所以只有 twmain 中招。

**這也解釋了為什麼調緊容差救不了**：容差控制的是平面偏離（本來就只有 1.9m），
控制不了「這段弦有多長」造成的測地線分歧。

## 修法

```sql
ST_Segmentize(ST_SimplifyPreserveTopology(line_geom, 0.0002), 0.05)
```
先簡化、**再把長弦切成 ≤0.05° 的小段**，讓每一段短到平面直線與測地線幾乎重合。

| | twmain 最大偏離（geography） | 目標案例 Δ vs 全解析度 |
|---|---|---|
| 只簡化 | 405.4 m | 0.172 浬 ❌ |
| 簡化 + segmentize | **19.9 m** | **0.0008 浬** ✅ |

頂點數 twmain 169 → 365（相對原始 6,503 仍壓縮 94.4%），其他三個 region 幾乎不變。

- Migration：`gis-platform/migrations/365_vessel_zone_segmentize.sql`
- 連帶要處理：trigger 上線後已用壞線寫入的列必須 **re-NULL**，
  否則回補的 `WHERE zone IS NULL` 會靜默跳過它們，變成一條沒人記得的分歧路徑

## 教訓（Learning）

- **這個坑通用** → 值得進 `PRINCIPLES.md`：
  **簡化幾何若之後要用 `::geography` 量距離，一律加 `ST_Segmentize`。**
- **量測的座標系要跟使用的座標系一致**。用平面距離驗收、卻用 geography 距離產出，
  驗收就等於沒做。本例三個錯誤全部源自這一點：
  1. 一開始憑「0.001° ≈ 111 公尺」推算容差 → 沒實測
  2. 掃描候選容差時用 `ST_Distance(geom, geom)` 平面度距離再乘 111320 換算
     → **得到的 41m / 20m 是 DP 保證的重述，不是真實誤差**，於是「證明」了一個錯的參數
  3. 子代理用單一案例驗收 → 那個點的最近點落在恆被保留的頂點上，三個容差給出一模一樣的浮點數
- **`ST_HausdorffDistance` 不能用來驗簡化品質**：PostGIS 那支是離散版只比頂點，
  而簡化線的頂點是原線的子集，會系統性低估（本例回報 104.7m vs 實際 385.9m）。
- **子代理反駁主 agent 的數字時要當真**：本例是子代理指出
  「41m ≈ 0.0004×111km、20m ≈ 0.0002×111km，這兩格看起來是容差換算不是實測」，
  主 agent 回頭查自己的 SQL 才發現真的漏了 `::geography`。**它是對的。**

## Meta

**做對的地方**：對「11 公尺容差造成 290 公尺誤差」起疑並實測，方向是對的。
子代理堅持把失敗的關卡交回而不是自行放寬容差，讓錯誤沒有被吞掉。

**做錯的地方**：整條路上**三次「憑推算下規格」**——
回補耗時（用單一 region 外推，錯 70 倍）、容差選值（用度數換算，錯到選了個沒用的參數）、
以及第一次診斷時把「容差 ≠ 偏離」當成完整根因（其實只是表象）。
**規格裡每一個數字都該有一次實測支撐，而且實測用的度量必須與正式路徑一致。**

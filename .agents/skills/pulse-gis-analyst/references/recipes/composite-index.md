# 複合指數：百分位／z-score／敏感度（關聯）

**適用**：「把好幾個指標合成一個生活品質分數來排名」「這幾區在食衣住行育樂哪裡比較好」「這個排名穩不穩、換權重會不會變」。

**工具鏈**：`pulse_sql` 一次抓每個地區的原始指標（各面向各一欄，例如密度、中位數），數學留給呼叫端算，不要在 SQL 裡硬湊 window function：
1. **百分位**（單面向相對比較，不需處理方向）：`(名次 - 1) / (n - 1) * 100`（名次從 1 起算，最低 0、最高 100；直接用名次除 n-1 會超過 100），同值取平均名次。
2. **z-score 合成**（要排名、要跨面向加總）：每面向先減平均除母體標準差；「越高越差」的面向（例如房價、風險）**乘 -1 反轉**再加總，等權直接加總（不用平均，排名不受影響）。
3. **leave-one-out 敏感度**：對每個面向，重算「排除該面向」的合成分數與名次，記錄每地區的最大名次變動，並算 Spearman：`1 - 6*Σ(d²) / (n*(n²-1))`，d = 兩次排名差。

**必帶但書**（自查用；對使用者只挑 1–2 句改白話「小提醒：」，不帶表名欄位代號）：等權是主觀選擇，換權重排名會變，必須明講「等權」；面向間高度相關時（例如房價和交通常同向）等權會重複計分；MAUP（換行政區尺度結果可能不同）；Spearman 低代表指數對某面向敏感，對外引用要註明是哪個面向、降到多少。

**停止**：排名表（含每區最大名次變動）＋ 逐面向剔除的 Spearman 相關 ＋ 一句「對哪個面向最敏感」。

**追問**（素材：從結果挑一個，照 SKILL「回答格式」改寫成一兩句問句，不照抄成清單）：要不要換權重（例如住的權重加倍）？要不要換城市／行政區尺度？要不要只看某幾個面向？
